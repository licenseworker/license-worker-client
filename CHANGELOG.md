# Changelog

All notable changes to this crate are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the crate follows
[Semantic Versioning](https://semver.org/).

## [0.3.1] - 2026-11-17

### Fixed

- **Rust client: a quiet re-activation could lock a paying user.** After
  `instance_id not found.`, `check()` adopted the new instance before its licence
  was verified. When the server's answer had no licence, or one that did not
  verify, the stored licence was then judged against the new instance and failed
  as `wrong_instance`, also offline. The new instance and its licence are now
  adopted only when that licence verifies; otherwise the new seat is given back
  and the app is judged by the licence it held. A signed revocation still locks.
- **Swift: the latest time seen survives a new activation**, and the activation
  is judged against it, as in the Rust client. The mark also moves forward at
  launch, not only when the server is asked.

### Changed

- `rust-version = "1.88"`, the lowest the locked dependencies allow; CI builds on it.
- Every public item is documented (`#![warn(missing_docs)]`), including why both
  public keys must be given (Rust, Swift and C).
- The C header has `LW_VERSION_MAJOR`, `LW_VERSION_MINOR`, `LW_VERSION_PATCH` and
  `LW_VERSION_STRING`.
- The `check:clients` command moved to `cli/`, a workspace crate that is not
  published: installing the crate no longer installs a test binary.
- A release runs the Rust and Swift tests before it tags anything.

## [0.3.0] - 2026-11-17

### Added

- **LicenseWorkerKit**, the client in Swift for macOS 12+ and iOS 15+, through
  Swift Package Manager (`import LicenseWorkerKit`). No dependencies beyond
  Foundation, CryptoKit and Security. A `LicenseController` state machine
  (an `ObservableObject`) over the same rules as the Rust crate: validation
  at most once a day, quiet re-activation, a high-water clock, the hand-over
  of an older app version's key, Keychain or file storage. A
  `LicenseWorkerKitTesting` library gives an app's tests a scripted server, a
  test signer and a movable clock. 55 tests, the 16 shared vectors among them.

### Changed

- **Swift Package Manager now serves LicenseWorkerKit, not the C interface's
  XCFramework.** A package that held both would make every Swift user
  download the XCFramework. The XCFramework stays a download on each
  Release for C, C++ and Objective-C. Projects that used
  `import LicenseWorker` through SwiftPM stay on 0.2.1, or move to
  LicenseWorkerKit.
- Releases tag the commit they built; `Package.swift` is no longer written by
  the release.

### Fixed

- Windows packages: `link-libs.txt` named `windows.0.53.0.lib`, an import
  library no C project has; it now lists the system libraries instead
  (`advapi32 secur32 crypt32 bcrypt ncrypt`).

## [0.2.1] - 2026-11-17

### Added

- Swift Package Manager: add this repository in Xcode and `import LicenseWorker`
  (iOS 13+, macOS 11+). `Package.swift` is written by the release, with the
  checksum of the XCFramework attached to that release.
- A Linux ARM64 (aarch64, glibc) package on each release.
- `PROTOCOL.md`: the three calls, the signed licence, the verification steps
  and the client rules, so anyone can run a compatible server or write a
  compatible client.
- `SECURITY.md`: how to report a security problem privately.

### Changed

- Releases are started by hand with the version (Actions > Release), which
  builds everything, then commits `Package.swift` and makes the tag.
- The workflows use actions that run on Node 24.

## [0.2.0] - 2026-11-17

### Added

- `capi/`: a C interface (`license-worker-client-capi`, library `license_worker`)
  for C and C++ apps and audio plugins. Opaque `LwClient`, plain `LwStatus`,
  `LwResult` and `LwState`, strings freed with `lw_string_free`; file or
  keyring storage; every call catches panics. Header generated by cbindgen and
  kept current by a test.
- `examples/`: a C command in the `check:clients` contract and a C++ plugin
  wrapper, built by CMake as static libraries, for Windows x64 and ARM64
  (optionally the static CRT) and universal macOS.
- `capi/build-apple.sh`: `LicenseWorker.xcframework` for iOS (device and
  simulator) and universal macOS, with a module map for Swift.
- CI builds and runs them on Linux, macOS and Windows, and builds the
  XCFramework.
- Prebuilt packages on each GitHub Release: Windows x64 and ARM64 (`/MD` and
  `/MT`), universal macOS, `LicenseWorker.xcframework` (iOS, iOS Simulator,
  macOS) and Linux x86_64.

### Changed

- The Rust crate is unchanged apart from its version.

## [0.1.0] - 2026-11-17

First release: the copy-paste Rust client and verifier from License Worker's
docs, packaged as one crate.

### Added

- `LicenseClient`: `activate`, `check`, `check_offline`, `deactivate`, with a
  blocking `ureq` 2 transport (Windows' own TLS on Windows, rustls elsewhere).
- The client rules: only a signed revocation locks; offline, the stored licence
  decides; a high-water clock; quiet re-activation on `instance_id not found.`;
  the seat is given back when the app refuses a licence.
- `verify`: the Ed25519 verifier of the signed licence `v1.<payload>.<sig>`,
  with kid-based key rotation, tested against the 16 shared test vectors.
- Storage: `FileStorage`, `MemoryStorage`, and `KeyringStorage` behind the
  `keyring` feature (Windows Credential Manager, macOS Keychain, Linux Secret
  Service). `default_instance_name()` from the computer name.
- `Transport`, so tests can script a server and run offline.
- The `license-worker-client` command, in the contract License Worker's
  `npm run check:clients` drives.
