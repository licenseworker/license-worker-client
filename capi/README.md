# license_worker: the C interface

The C ABI of [license-worker-client](../README.md), for C and C++ apps and
audio plugins (VST3, AU, AAX, CLAP). It is the same Rust client underneath,
so it follows the same rules: only a signed revocation locks, offline the
stored licence decides, the high-water clock, both public keys, quiet
re-activation on `instance_id not found.`, and the seat given back when the
app refuses a licence.

- Header: [`include/license_worker.h`](include/license_worker.h), generated by
  cbindgen from [`src/lib.rs`](src/lib.rs). A test fails when they differ.
- Library: `license_worker` from this crate (`license-worker-client-capi`),
  as a static library (`liblicense_worker.a` / `license_worker.lib`) or a
  shared one.
- Examples: [`examples/c/lw_cli.c`](../examples/c/lw_cli.c) (every call, as a
  command) and [`examples/cpp/plugin_licence.cpp`](../examples/cpp/plugin_licence.cpp)
  (a small RAII wrapper, the way a plugin holds it), built by
  [`examples/CMakeLists.txt`](../examples/CMakeLists.txt).

## Prebuilt packages

Each [GitHub Release](https://github.com/licenseworker/license-worker-client/releases)
carries ready-built packages, so nothing needs a Rust toolchain:

| Package | Platform | Inside |
|---|---|---|
| `license_worker-<tag>-x86_64-pc-windows-msvc-mt.zip` | Windows x64, static C runtime (`/MT`, usual for plugins) | `license_worker.lib`, `license_worker.dll` + `.dll.lib` |
| `license_worker-<tag>-x86_64-pc-windows-msvc-md.zip` | Windows x64, DLL C runtime (`/MD`) | same |
| `license_worker-<tag>-aarch64-pc-windows-msvc-mt.zip` / `-md.zip` | Windows on ARM64 | same |
| `license_worker-<tag>-macos-universal.zip` | macOS 11+, arm64 and x86_64 | `liblicense_worker.a`, `liblicense_worker.dylib` |
| `LicenseWorker-<tag>.xcframework.zip` | iOS 13+ (device), iOS Simulator (arm64, x86_64), macOS 11+ | static libraries, header and module map (`import LicenseWorker` in Swift); `.sha256` beside it |
| `license_worker-<tag>-x86_64-linux-gnu.tar.gz` | Linux x86_64 (glibc) | `liblicense_worker.a`, `liblicense_worker.so` |
| `license_worker-<tag>-aarch64-linux-gnu.tar.gz` | Linux ARM64 (glibc): Raspberry Pi OS 64-bit, ARM servers | same |

Every package has `include/license_worker.h` and `link-libs.txt`, the system
libraries to link with the static library, printed by rustc for that very
build. Windows, macOS and the XCFramework are built with the `keyring` feature
(Credential Manager, Keychain); the Linux package is not, so it needs no
libdbus: give it a `storage_path`.

## Plugins link statically

A plugin is a guest in someone else's process: link `license_worker`
**statically**, so there is no DLL or dylib to ship, to sign, or to clash with
another plugin's copy. Every symbol is prefixed `lw_`.

Build it with CMake beside your plugin (JUCE and the VST3 SDK are CMake
projects), reusing `examples/CMakeLists.txt`'s rules, or with cargo:

```sh
cargo build --release -p license-worker-client-capi --features keyring
# target/release/liblicense_worker.a, or license_worker.lib on Windows
```

| Platform | Build | Link with |
|---|---|---|
| Windows x64 | `cargo build --release -p license-worker-client-capi --target x86_64-pc-windows-msvc` | `license_worker.lib kernel32 ntdll userenv ws2_32 dbghelp synchronization advapi32 secur32 crypt32 bcrypt ncrypt` |
| Windows ARM64 | same, `--target aarch64-pc-windows-msvc` | same |
| macOS universal | `cargo build` for `aarch64-apple-darwin` and `x86_64-apple-darwin` with `MACOSX_DEPLOYMENT_TARGET` set, then `lipo -create` | `liblicense_worker.a -framework Security -framework CoreFoundation -liconv` |
| Linux | `cargo build --release -p license-worker-client-capi` | `liblicense_worker.a -lpthread -ldl -lm` (and `-ldbus-1` with `keyring`) |

| iOS, iOS Simulator, macOS | `capi/build-apple.sh [--keyring]`: one `LicenseWorker.xcframework` | `-framework Security -framework CoreFoundation -liconv` |

The CMake file does the Windows, macOS and Linux rows: `-DCMAKE_OSX_ARCHITECTURES="arm64;x86_64"`
for a universal macOS library (deployment target 11.0 by default,
`CMAKE_OSX_DEPLOYMENT_TARGET` to change it), `-A ARM64
-DLW_RUST_TARGET=aarch64-pc-windows-msvc` for Windows on ARM, and
`-DLW_KEYRING=ON` for the OS credential store.

**iOS and macOS apps.** `capi/build-apple.sh` builds `build/apple/LicenseWorker.xcframework`
with three static slices: `ios-arm64`, `ios-arm64_x86_64-simulator` and
`macos-arm64_x86_64` (deployment targets iOS 13.0 and macOS 11.0, set by
`IPHONEOS_DEPLOYMENT_TARGET` and `MACOSX_DEPLOYMENT_TARGET`). Drag it into an
Xcode target and add `Security.framework`; it carries `license_worker.h` and a
module map, so C, C++, Objective-C and Swift (`import LicenseWorker`) all use
it. With `--keyring` the licence can live in the Keychain on both. On iOS the
licence is kept per app: set `cfg.keyring_service`, or a `storage_path` inside
the app's container.

The exact list depends on the Rust version: `cargo rustc --release -p
license-worker-client-capi --crate-type staticlib -- --print native-static-libs`
prints it for yours.

**Swift Package Manager.** In Xcode, File > Add Package Dependencies, the URL
`https://github.com/licenseworker/license-worker-client`, then `import
LicenseWorker`; or in a `Package.swift`:

```swift
.package(url: "https://github.com/licenseworker/license-worker-client", from: "0.2.1"),
// and in the target:
.product(name: "LicenseWorker", package: "license-worker-client"),
```

It downloads the XCFramework of that release (checked against the checksum in
the tag's `Package.swift`) and links Security and CoreFoundation for you. The
C functions are then plain Swift calls: `lw_check(client, &status)`.

**Windows C runtime.** Plugins usually build with the static CRT (`/MT`).
Rust links the DLL CRT unless told otherwise; build it with
`RUSTFLAGS="-C target-feature=+crt-static"` to match (`-DLW_MSVC_STATIC_CRT=ON`
in the CMake file), or the link fails on a CRT mismatch.

HTTPS uses Windows' own TLS (schannel) on Windows, so the library needs no C
toolchain beyond MSVC and trusts the Windows certificate store, and rustls
elsewhere, so nothing depends on OpenSSL.

## Using it

```c
#include "license_worker.h"

const char *kids[] = {"k1", "k2"};
const char *keys[] = {"<active public key, base64>", "<backup public key, base64>"};
int64_t products[] = {900000001};

LwConfig cfg = {0};                        /* zero means "the default" */
cfg.server_url = "https://license.example.com";
cfg.key_ids = kids;
cfg.public_keys = keys;
cfg.key_count = 2;                         /* embed both */
cfg.product_ids = products;
cfg.product_count = 1;
cfg.keyring_service = "com.example.myplugin"; /* with the keyring feature; or cfg.storage_path */

char *error = NULL;
LwClient *client = lw_client_new(&cfg, &error);
if (!client) { show(error); lw_string_free(error); return; }

/* The licence window. */
LwStatus st = {0};
char *message = NULL;
if (lw_activate(client, key, &st, &message) != LW_RESULT_OK) show(message);
lw_string_free(message);
lw_status_clear(&st);

/* At start-up, off the audio and UI threads. */
lw_check(client, &st);
licensed = st.unlocked;                    /* e.g. a std::atomic<bool> the processor reads */
lw_status_clear(&st);

lw_client_free(client);
```

### The contract

- **No panics cross the boundary.** Every function catches them and answers
  `LW_RESULT_PANIC` (or NULL from `lw_client_new`).
- **Strings in** are UTF-8 and NUL-terminated, borrowed for the call.
  **Strings out** are yours: free them with `lw_string_free`. An `LwStatus`
  owns its `reason`: free it with `lw_status_clear`.
- **NULL** is fine for every optional out-parameter (`error`, `message`,
  `status` of `lw_activate`), and refused with `LW_RESULT_INVALID_ARGUMENT`
  elsewhere.
- **Threads.** `lw_activate`, `lw_check` and `lw_deactivate` block on the
  network (up to the timeout, 10 s by default, a few times over). Never call
  them on the audio thread or the UI thread. A client may be used from any
  thread, one call at a time. `lw_check_offline` makes no request; it is
  fast enough for start-up, but it still reads storage, so keep it off the
  audio thread too.

| Function | Does |
|---|---|
| `lw_client_new(cfg, &error)` | Creates a client. No request. |
| `lw_activate(client, key, &status, &message)` | Activates and stores. On failure nothing stored changes; `message` is for the user. |
| `lw_check(client, &status)` | Validates online, else judges by the stored licence. |
| `lw_check_offline(client, &status)` | Judges by the stored licence, no request. |
| `lw_deactivate(client, &message)` | Frees the seat, forgets once the server confirmed. |
| `lw_status_clear`, `lw_string_free`, `lw_client_free` | Free what the library gave you. |
| `lw_default_instance_name`, `lw_version`, `lw_result_name` | Small helpers. |

`LwResult`: `LW_RESULT_OK`, `UNREACHABLE` (no usable answer), `REFUSED`
(with the server's message), `NOT_FOR_THIS_APP` (the seat was given back),
`STORAGE`, `INVALID_ARGUMENT`, `PANIC`.

## Tests

```sh
cargo test -p license-worker-client-capi       # the ABI contract, and the header is current
cmake -S examples -B build/examples -DCMAKE_BUILD_TYPE=Release && cmake --build build/examples --config Release
examples/c/smoke.sh build/examples/lw_cli      # the C example, offline
```

End to end, against a real local License Worker (in the license-worker repository):

```sh
LW_C_CLIENT=../license-worker-client/build/examples/lw_cli npm run check:clients
```

The C example passes the same 11 steps as the TypeScript, Swift and Rust
clients, on macOS and also built for the iOS Simulator and run in it through
`xcrun simctl spawn` (environment passed as `SIMCTL_CHILD_*`).
